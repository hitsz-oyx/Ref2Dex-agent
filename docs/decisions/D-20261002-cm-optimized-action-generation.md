# 从随机候选筛选转向Cm生成可执行动作

需要决定：继续改随机组合预测网络，还是让现有Cm的后果梯度实际决定候选？
选择后者。Mission、最终claim和完整goal保持；不派生子代理。

关键证据：HF19完成3745个真实H10窗口。H10支持高度误差改善约14.2%，但
一步dv/几何没有5%动作信息增益；原Probe UNPROMISING保留并关闭slot2。
离线选择器改变18.4%参考，vs强cup只有−.089mm，vs直接评分+.078mm，
区间跨0。随机组合池均值远差于cup，没有证据继续当前随机排序配方。
当前问题包含如何构造真正好的、状态相关候选，不能仅靠更久拟合来回答。

行动：冻结已审计Cm和专家，先做有界工程，把32步梯度优化接到每块六专家
权重simplex；腕部旋转仍锚定，XYZ/各指PD仍经原生耦合、在实测专家可执行
域内。目标用Cm预测的H10联合支持高度，扣成员相对分歧和预测几何损失；
不对端点力积分、不伪造全obs、不依赖长期V、不对未知候选补假真值。
这是让Cm产生动作的控制接口变化，区别于HF19只从六个随机组合中选一个；
不是复活原信息/选择器门或更换它的metric。

工程先验证真实bank上的梯度、权重/PD/锚定约束、专家冻结、优化计算上限，
以及在线pre-only输入与已有已审计输入一致。随后在新卡中固定生成器实际
机会Probe：base、cup、Cm生成、直接任务评分生成、shuffled生成及随机程序；
同候选域/优化步数/预算，随机实际执行H10。记录全部生成轨迹/预测及真实
片段；预测更高不等于真实更好。不确定性是规划约束，不阻止安全有界的随机
采集获得新真实标签。只有生成动作的真实机会通过才再适配Cm并测闭环重规划。

预计两Probe，各<=60min/8GiB，默认GPU1空闲时单GPU；首轮工程目标<=5min，
每决策优化固定32步，不扫描步数/lr/风险系数。已有随机源/Cm只作共享输入，
全部借用数据和预训练成本另报；旧HF19预算/失败门保留。若原生生成动作未
超过强参考或风险门失败，停止此配方，不投入PPO/完整成功率矩阵。
新科学Probe在工程通过后才登记固定卡，不从本Memo直接启动科学长任务。
全部边界在现有用户授权与CAMPAIGN内；没有需要新增外部授权的操作。
