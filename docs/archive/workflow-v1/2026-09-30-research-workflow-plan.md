# 科研工作流实施计划

依据：已由用户确认并要求实施的 [规格](../specs/2026-09-30-research-workflow-design.md)。
执行方式：当前代理在独立工作流工作树逐项实施；审查使用两个只读代理。
writing-plans skill 本机未安装，本文件承担实施步骤与验证清单，不增加运行规范。

1. 在公开 researchctl CLI 验证 campaign 总截止可选、单任务仍有界；保留显式预算回归。
2. 加入持久用户指令和版本，暂停/恢复/改目标淘汰旧决定；后台唯一 owner 应用最新指令。
3. 加入受阻、重要自主决定与正式完成的公开决定；记录输出可重建，验收证据与目标版本关联。
4. 加入按角色配置的独立 provider 备选及任务 provider 指定；恢复/续接使用原始绑定，未知投递不切换。
5. 收敛 AGENTS 与 workflow 文档，建立显式会话归属和独立工作树保护，保持原科研资源权限。
6. 简化新 Probe 模板，生成按路线分组的索引，保留原卡片/ID/证据路径和 Validation 严谨要求。
7. graspenv 定向回归、类型检查、真实 Orchestrator smoke；检查可用真实账号的小型 CPU 回合；全仓测试一次。
8. Standards/Spec 两轴审查、修复、记录实际验证边界并提交；不停止活跃实验，不自动 push 或部署切换。

每个行为切片先写公开 CLI 的失败用例，再实现。执行层用独立测试进程替代外部模型，
不 mock 本仓库内部协作方法。文档与索引不对历史科研结论重新定性。

实施结果与已知验证边界见 [验证记录](../../archive/workflow-v1/VALIDATION_20260930.md)。8 项实施步骤已完成；现有 campaign 切换仍为单独操作。
