# Statistical option learning after replay matching fails

Question: keep repairing exact simulator replay, or evaluate trained option
policies using randomized matched conditions without a same-state oracle?

Evidence:601initial tensors/first commands match but subsequent physical
prefixes diverge;605rules out measured per-actor property differences;
zero-origin engineering fails too. None permits a conditional oracle claim.
Joint options are actually executed and have differing task outcomes; their
random mean is worse than P0, so improvement cannot be inferred from a
retrospective maximum. Original compact/support value screens remain closed.

Decision: stop further layout/precision/matching-limit tuning. The next learning
design must use each environment's ACTUAL state at the option decision, and
measure deployed trained-policy outcomes in fresh randomized arms. Preserve
P0 fallback, common P0 prefix, task105 and original spaced scene. Old601may be
disclosed as inspected exploratory development evidence, never final TEST.

Candidate design to make concrete next: collect new randomized joint-option
FIT data; learn a short physical successor Cm and a continuation-value model
for the held option; train an option actor against their composed task return.
Matched Cm-off removes action input from the successor model while keeping
the same observed state, value/actor architecture, physical data and optimizer
budget. A direct task-Q trained actor is a strong additional control. All
actors are self-trained residuals over P0; prospective evaluation runs actors,
not retrospective maxima. Pretraining interactions/compute must be reported.
This is a design candidate, not a frozen experiment or a positive method claim.

Before launching, freeze successor horizon/targets, candidate coverage,
model/actor regularization, exact update/evaluation budgets, meaningful primary
success gates and stop conditions. Model exploitation and continuation-policy
consistency need explicit handling; future task values cannot be replaced by
motion amplitude. No architectural commitment based on the failed oracle.
No new permission or change to Mission/claim/resource bounds is required.
