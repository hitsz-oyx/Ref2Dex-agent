# Ref2Dex 精简科研工作流设计

状态：讨论方案已确认；本书面规格待用户审阅。
日期：2026-09-30。实施分支：`agent/workflow-runtime-adoption`。
本规格是设计记录，不是新增的日常必读规范；尚未修改运行行为或切换现有 campaign。

## 1. 目标与已确认要求

用户只与科研主代理讨论目标、查询进度和调整方向。主代理自主选择最小有价值任务，
按需启动固定职责的 worker，验收证据并继续推进。执行后端管理进程、日志与任务状态。
独立账号/provider、关闭前台后后台续接、可靠暂停和有限故障恢复继续保留。

用户确认以下要求：

- 文档与运行代码一起精简；角色固定，会话和 provider 可替换。
- 用户自己新建的普通会话独立于科研调度，直接执行用户任务。
- 科研代理不接管、修改或停止独立会话的工作；成果只在用户明确交付后进入科研记录。
- 自主推进不设指定小时窗口，持续到最终任务完成，或用户主动暂停、打断、改变目标。
- 自主期间不主动提问或寻求路线选择；用户主动查询时正常回答。
- 重要的自主决定简短留痕，普通命令、修复和重试不写决策流水账。
- 最终完成以 MISSION 的可验证目标为准，不能以单次 Probe 或 worker 完工替代。

## 2. 会话归属与控制

会话归属和推进状态是两个维度：

| 维度 | 状态 | 含义 |
| --- | --- | --- |
| 会话归属 | 独立会话（默认） | 用户直接控制，不加入角色池，不受科研派发/验收流程约束 |
| 会话归属 | 科研 root/worker | 显式加入工作流，使用绑定的职责、权限与工作树 |
| 推进状态 | 持续自主 | 在已有授权与预算内继续，不主动联系用户 |
| 推进状态 | 暂停 | 停止新派发，已启动实验收尾，保存结果 |
| 推进状态 | 等待/受阻 | 暂无可执行任务、资源不足或故障需要外部变化；不宣称任务完成 |
| 推进状态 | 完成 | MISSION 验收通过，停止新派发并保存完成摘要 |

会话加入科研工作流需要显式角色绑定；仅打开仓库、使用某个 provider 或某个分支名
不构成加入。持续自主在用户启动科研任务时明确开启，不因后台重启而丢失，也不自动
把独立会话变为科研代理。

根目录 AGENTS 只保留通用工作区保护、用户指令优先、模式选择与阅读入口。
科研专属规则由已加入工作流的代理按需读取，普通会话不需要 root 批准、角色派发或
科研验收。独立会话仍保护已有修改、未知进程、数据和明确的资源/工作区边界。

科研工作使用独立工作树。发现独立工作与当前任务冲突时，优先避开路径、换工作树、
换任务或等待；不得覆盖用户修改、自动合并独立成果、抢占进程或要求独立会话服从 root。
普通交互时可以向用户说明冲突；持续自主期间只记录影响路线的冲突并等待用户查询。
无需扫描独立会话历史来确认其内容或干预其运行。

## 3. 主代理与执行层

保留 Codex root、外部 Orchestrator 和一个轻量后台监督入口。

1. 前台将用户目标、调整与控制指令写入持久入口，返回已接收状态。
2. 唯一后台 owner 读取最新指令、研究状态与当前执行结果，调用有界 root 决策回合。
3. root 选择任务、验收交付、等待、报告阻碍或提出最终完成。
4. 确定性入口检查职责、资源、工作树、用户控制状态与任务幂等性，再应用决定。
5. worker 交付代码、结果与证据位置；root 根据证据更新判断并继续。

前台与后台共享同一控制入口。指令有递增版本；执行决定关联其读取的版本，用户暂停
或改变目标后不应用旧版本的推进决定。状态查询显示已接收与已处理版本，不能把前台
答应了用户等同于后台已经收到。前台不是第二个自动派发 owner。

用户指令为事实来源，聊天记录不作为后台必须恢复的长期身份。任务关联与验收保存在
本机控制状态；完整执行状态从后端读取，不再另建一套进程状态镜像。

Pause 始终优先于推进与恢复。暂停后不新启动 root 或 worker，不消费尚未应用的推进
决定；现有实验可收尾。用户明确 interrupt 实验时才中断指定、可确认归属的进程。
投递响应丢失时按唯一名称 reconcile，无法确认则等待，不盲目重发。

## 4. 持续自主与边界

持续自主取消人为设置的运行小时窗口，不取消任务 timeout、GPU/磁盘/账号支出预算，
也不以重启、恢复或新建子任务重置已消耗预算。已有 campaign 的明确上限继续有效。
当前实现的总 wall time、dispatch 数和 root 回合数限制必须在配置中明确区分：哪些是
已授权资源上限，哪些只是旧循环的默认截止；不能默默把所有限制改成无限或自动续费。

root 可以自主更换探索路线、调整实现、处理失败、停止无效局部方案并重新分配已授权
资源。普通局部任务完成后继续选下一项，不能因前台关闭而退出科研监督。

涉及改变最终研究问题/成功条件、扩大资源或权限、创建新长期角色、不可逆外部操作，
若超出现有授权则不执行；记录阻碍，继续其他已授权工作。持续自主免除的是主动询问，
不是自动扩大授权。预算耗尽或没有安全可执行路线时进入等待/受阻，不循环空调用模型。
恢复遵循有限退避；达到故障上限停止该恢复路径，保留状态，不无限恢复原生 Goal。

三次有效 Probe 无信息增益时进行路线复盘，由 root 自主决定换路线，并记录重要选择。
负向 Probe 只关闭对应局部方案；不因此修改 MISSION 或把整个任务标为完成。

用户主动询问时，回答当前进展、重要决定、证据、资源剩余和阻碍，不夹带必须回答的
审批问题。用户主动调整目标或授权时更新持久指令，再按新范围继续。

## 5. 角色与 provider

`docs/AGENT_ROLES.yaml` 是固定职责和权限的唯一 tracked 来源。

| 角色 | 职责 | 典型交付 |
| --- | --- | --- |
| root | 选题、派发、证据验收、集成、完成判断 | 任务、验收理由、当前研究判断 |
| cm | 表征、物理预测、机制研究 | 方法实现、信息增益与机制证据 |
| rl | 策略训练、仿真接入、在线实验 | 策略、运行 manifest、策略指标 |
| eval | 指标、配对检查、独立证据审查 | 可复核评估与结论边界 |
| infra | 数据、工具、测试、运行基础设施 | 可复现工程实现和验证结果 |

本规格不自行扩大现有角色的 GPU/实验权限。职责摘要由唯一角色定义提供给 worker，
任务中注明目标、边界、预算、停止条件和交付，不要求 worker 阅读全套管理文档。

账号/provider、CODEX_HOME、工作树和执行 store 留在本机配置，凭据不提交。
主代理在已配置且验收过的绑定中选执行者；不静默切换账号或创建新长期身份。
模型 harness 当前仍沿用已验证的 Codex 路径；其他 harness 的接入另行验收。

## 6. 文档归属

| 入口 | 唯一职责 |
| --- | --- |
| AGENTS.md | 通用规则、会话归属、按需阅读入口 |
| docs/MISSION.md | 最终目标、成功条件与科研优先级 |
| docs/STATE.md | 当前关键事实、判断、blocker 与证据链接，目标为一屏摘要 |
| docs/CAMPAIGN.md | 人可读的资源和授权边界 |
| docs/workflow/README.md | 唯一日常工作流说明：启动、派发、查询、暂停、恢复和失败处理 |

角色 YAML 是职责/权限来源，本机配置是实际绑定与可执行预算来源。配置必须在 CAMPAIGN
授权内；冲突时采取较严格边界并保存原因，不能任选宽松值。运行摘要从状态查询产生。
RESEARCH_QUEUE 如需保留，专门保存路线候选和 family 搜索预算，不复制实际运行状态。

合并 workflow 的架构/操作核心内容到 README。迁移设计、ADR、验证报告与历史合同按需
检索，不成为额外必读规范。旧入口只保留必要兼容跳转，旧任务收尾结束后再清理依赖。
本规格自身属于设计记录，不引入另一份需要持续同步的工作流规则。

## 7. Probe 与工作记录

按决策问题组织实验。同一冻结设计中的 seed、对照臂和技术重试归入 run_id；工程 smoke
和普通 bug 修复不新增科研 Probe。改变研究问题、实验设计或判定条件时明确记录新实验
或设计修订，保留各次执行，不通过合并隐藏失败、筛选或事后调整。

实验卡开头保留短摘要：问题、最小方法、关键结果、改变的决策、结论边界、证据链接。
详细配置、命令、输入哈希、代码版本和执行状态保存在 manifest；正式 Validation 继续
保留 matched control、多 seed、预先判定与完整证据。科学证据要求不因记录精简而降低。

生成按研究路线组织的实验索引，展示问题—结果—下一步，链接原始实验卡。
索引由实验卡生成，不人工维护第二份台账。STATE 只更新改变当前判断的结果；handoff
只给交付摘要与链接，不复写实验卡。历史记录原样保留，迁移不得破坏实验 ID 或证据链接。

## 8. 自主决策记录

科研工作流维护一份当前自主决策记录，完成或显式开启新目标后归档。
记录研究范围、启停状态和重要自主决定，属于研究决策证据，不是运行日志。

仅记录原本值得请示、此次由 root 在已有授权内自主决定的大事：主要路线切换、重要
局部假设的放弃、较大资源重分配、影响路线的独立工作冲突，以及超授权的受阻事项。
每条包含：决定、关键证据及链接、选择理由、成本/停止条件、执行结果或未解决事项。
结果改变该决定时更新同条记录；普通命令、修复、参数细调、心跳和重试不记。

该记录不得包含凭据，不复制实验细节。用户询问进度时结合 STATE、执行状态和重要
决定解释进展。没有新证据时不生成重复决策或重复调用模型。

## 9. 最终完成

完成必须同时满足 MISSION 的自训练操作目标与 Cm 对实际策略的可验证贡献要求，
并以对应任务范围的正式 Validation 和 matched Cm-on/off 证据支撑。
具体实验的任务范围、指标、seed 与门槛在查看结果前固定；本规格不编造新的数值门槛，
不将单个 worker 完工、单次 rollout、Probe 正信号或负向路线关闭作为总体完成。

eval 审查证据与有效性，root 给出逐项目标的证据映射和验收理由后提交完成决定。
完成判定与用户最新目标版本绑定；确定性入口要求证据引用、明确验收和无待处理的
影响结论交付，并尊重更新后的用户控制状态。控制验证本身不能证明科研结论。
成功后停止新派发，保存完成摘要；不自动 push 或对外发布。用户询问时提供最终结果。
未达到目标且预算耗尽/受阻时显示未完成，不降低目标冒充成功。

## 10. 验证与迁移

公开入口验证至少覆盖：普通会话不被注册或科研规则接管、独立修改/进程不受干扰、
用户指令确实到达后台、控制版本竞争、暂停与恢复、前台关闭后的持续推进、预算不被
重置、未知投递不重复执行、有限恢复、重要决定留痕、索引与原卡一致，以及未满足
MISSION 时拒绝总体完成。

小规模真实账号验证覆盖两个 provider/账号不串用、root 决策输出及后台 worker 交付。
工程 smoke 不能替代真实账号和科研结论验证。既有依赖公告及运行边界继续按先前验证
记录处理，不能把本次设计批准表述成上线验收通过。

旧任务由旧系统收尾，新系统只接新任务；切换必须保证唯一派发 owner，不干扰旧实验。
先完成规格审阅与实施计划，再修改代码。此阶段只提交本设计，不改现有运行配置、
代理绑定、研究结果、其他会话工作或活跃进程。
