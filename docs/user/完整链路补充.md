对，**后面真正接 PointWorld 时，最好有一个 ACT-like 的 action-chunk baseline**。但原因不是“PointWorld 必须配 ACT”，而是我们缺一个：

\[
\boxed{H_t\rightarrow A^{desired}_{t:t+23}}
\]

即在当前时刻就能一次性给出未来 24 步候选动作的 proposal policy。

现在的 PPO/expert 是反馈策略：

\[
a_t=\pi(H_t)
\]

下一步动作要等 \(H_{t+1}\) 才知道，所以严格来说，你在 \(t\) 时刻并不知道完整的未来 24 步 action。这个和 PointWorld 当前需要的“已知 future hand-flow/action chunk”并不完全匹配。

所以后面可以变成：

\[
H_t
\xrightarrow{\text{ACT-like}}
A^{base}_{1:24}
\]

围绕 baseline chunk 生成多个候选：

\[
A_1,\ldots,A_8
\]

再：

\[
A_i^{desired}
\xrightarrow{\text{Execution Model}}
\hat A_i^{exec}
\xrightarrow{\text{PointWorld}}
\hat Z_i
\xrightarrow{\text{Evaluator}}
\hat Y_i.
\]

选：

\[
i^*=\arg\max_i\hat Y_i
\]

然后只执行前 \(4\sim8\) 步，再重新规划。

### 我为什么倾向 ACT，而不是直接继续用 PPO

ACT 有三个优点正好适合我们：

- 天然输出 action chunk；
- 整个 chunk 在决策时刻已知，满足我们的因果接口；
- 可以直接用现有成功机器人 rollout 做 imitation，不需要再做 RL。

第一版甚至不用做很大的 ACT。我们的目标不是证明 ACT 很强，只需要得到一个**稳定的共同 baseline/proposal generator**。

训练数据直接用：

\[
(H_t,\ a_{t:t+23}^{expert})
\]

其中 expert trajectory 来自我们已有的成功 Gym rollout。

然后 baseline 对照非常干净：

\[
\boxed{
\text{ACT only}
\quad vs\quad
\text{ACT + candidate ranking}
}
\]

这样最后 PointWorld 有没有帮助就很好解释。

不过有一点我建议提前定好：**ACT 输出最好还是机器人 native action / joint target chunk，而不是直接输出 hand point-flow。**

然后：

\[
A^{native}
\rightarrow \text{FK}
\rightarrow A^{desired}_{hand-flow}
\]

PointWorld 使用 hand-flow；后面的 execution model 再处理：

\[
A^{desired}_{hand-flow}\rightarrow A^{exec}_{hand-flow}.
\]

这样控制层和世界模型层不会混在一起。

所以整个最终系统我现在会画成：

\[
\boxed{
H
\rightarrow
\text{ACT baseline}
\rightarrow
\{A_i^{native}\}
\rightarrow
\text{desired hand flow}
\rightarrow
\text{Execution Model}
\rightarrow
\text{PointWorld}
\rightarrow
\text{Evaluator}
\rightarrow
\text{选动作}
}
\]

短前缀执行，再闭环重规划。

**因此，你这个想法是对的：如果我们最后要认真验证 PointWorld imagination，而不是只做 oracle experiment，一个 ACT-like chunk baseline 基本是需要的。**不一定非得是 ACT，但必须有一个“当前状态一次性产生未来 action chunk”的模块；ACT 是目前最直接的选择。
