# PTv3-Shared-WAM：当前实现架构

依据：[ref1.md](ref/ref1.md)，goal编码按[ref1_1.md](ref/ref1_1.md)，共享条件路由按
[ref1_2.md](ref/ref1_2.md)更新。实现日期：2026-10-13。
这是独立 Task 的 supervised baseline；代码 schema 为 `ref2dex.ptv3-shared-wam.v1`。
当前已实现模型、三域预训练、机器人联合微调、可选 human replay、DDP、checkpoint
恢复以及原生仿真的 chunk 执行入口。工程验证与后续科学实验须分开解读。

## 1. 核心计算图

```mermaid
flowchart TD
    S[已观测场景 H4 的几何与动力学特征] --> P[Scene Projector + 原 PTv3-small]
    P --> ST[256 scene tokens]
    H[当前 2×11 手点及 H4 动力学] --> HT[HandTokenEncoder：22 个独立语义 token]
    ST --> Z[共享 Interaction Transformer：4 层 / 128D / 4 heads]
    HT --> Z
    Z --> U[Scene Future Head：物体点查询读取共享 Z]
    Z --> HG[取共享 Z 的 22 个手 token]
    G[32个当前点与t+24终态delta：每点6D] --> GT[GoalTokenEncoder：MLP + target embedding + goal type]
    GT --> Z
    HG --> V[Hand Future Head：每手点自身预测未来24步]
    V --> R[Chunk-R]
    RS[当前机器人状态87D] --> R
    R --> A[8×12 原生独立命令]
    A --> Q[执行缓冲：K_exec=1 / 4 / 8]
    Q --> PD[原生18D耦合 / clamping / PD / 仿真]
```

公式为：

\[
Z=F_{shared}(S_{\le t},H_{\le t},G),\qquad
\hat U=D_U(Z;P_t),\qquad
\hat V=D_V(Z),\qquad
\hat A=R(s_t,\hat V).
\]

`P_t` 是当前物体采样点，用来确定 scene head 的读取位置，不含未来信息。
两个 head 的交互上下文均来自共享 Z；scene head 没有绕过共享 trunk 的 PTv3
feature skip。goal通过共享交互层同时影响U和V；仍没有 `V → U` 路径。

当前正式goal合同为：

\[
\Delta P_G=P^{goal}_{t+24}-P_t,\qquad
G_t=\{[p_i,\Delta p_{G,i}]\}_{i=1}^{32},\qquad
g_i=\operatorname{MLP}([p_i,\Delta p_{G,i}]/0.05)+E_{target}.
\]

这里的终态是当前24步horizon的终点，不是整条543帧任务的最终放置位置。
第一版不输入+8/+16 waypoint，不压缩成9D刚体位姿；中间接近、闭合、抬升时序由
demonstration监督学习。32个点的delta可以随点变化，因此保留刚体旋转信息。
`E_target` 是可训练128D类型向量，初始化为零。

**本轮架构决策：**用户明确指定ref1_2，覆盖ref1/ref1_1中goal仅进入手分支的规定。
选择对称task conditioning，让U/V都使用endpoint任务条件；本轮成本限定为合同测试和
短工程smoke，完成后再进入三域预训练→airplane适配。R仍接收当前机器人状态和预测轨迹。

因此scene head学习的是 `p(U|S,H,G)`：训练数据的goal来自实际t+24 endpoint，
它可以直接提示目标物体终点。当前scene EPE不能作为独立因果世界模型或任意goal
反事实正确性的证据，也不能仅凭h24低误差判断中间运动已学会。
第一版沿用现有 Chunk-R 的87D状态合同；包含 q/dq、手与物体几何和物体速度，
没有新增 previous-command 维度。robot proprioception 不进入共享预测器。

## 2. 输入、坐标与掩码

所有预测使用同一个**当前 anchor frame**，单位为米。历史帧、当前手点、当前场景点和
计划 goal 都先转换进这个坐标系；未来不能单独重新居中。

| 字段 | 张量 | 用途 |
|---|---|---|
| `xyz` / `features` | B×P×3 / B×P×18 | 当前场景几何、法线、历史动力学和已有元数据 |
| `point_valid` | B×P | 可变长度场景的当前点掩码 |
| `start_hand` | B×2×11×3 | 当前手点坐标 |
| `start_hand_history` | B×2×11×9 | H4 速度、加速度、三步位移 |
| `start_hand_valid` | B×2×11 | 当前语义手点有效性 |
| `scene_points` | B×O×32×3 | 每个物体当前固定采样点 |
| `start_object_points` | B×32×3 | 目标物体当前点，独立goal token编码使用 |
| `goal_object_delta` | B×32×3 | 对应点的 t+24 目标位移，通过共享trunk影响双头 |
| `goal_object_points` | B×32×3 | 旧loader/计划pose的endpoint传输字段；模型不直接读取 |
| `object_goal_valid` | B×32 | goal 点掩码；缺失token清零并被attention排除 |
| `native_state` | B×87 | 仅机器人 R 使用 |

H4 在30Hz上表示当前和前三帧。启动时重复已有初帧，沿用其他 Task 的历史合同。
手顺序是 **right、left**；每手语义顺序为 wrist、五个 MCP、五个 fingertip。
机器人单右手时左手全部缺失，不用零坐标冒充有效点。

未来 `action`、`effect`、轨迹标签和监督有效性掩码均不进入共享编码器。
无效观察在进入 MLP/attention 之前清零，避免 NaN 通过梯度污染有效参数。
填充物体和缺失手的预测输出为零，loss 仍按显式掩码排除它们。

三域、机器人及在线输入都经 `shared_collate` 调用 `endpoint_delta`，将传输的
start/endpoint转换成显式delta。两组点先按有效性清理，再相减；缺失goal点的delta为零。
GoalTokenEncoder直接读取delta，不再次减去start，不读取absolute endpoint。
两部分各自按固定0.05m尺度归一化；这不是从验证集拟合的新统计。

## 3. 场景编码与共享交互层

复用 `goal-point-wam` 的 `SceneHistoryEncoder` 所构造的 **原 PTv3-small**，
不修改 vendor 的层数、通道、stride 或注意力结构。场景投影仍为18→128→128。
继承类移除没有使用的旧 object projector，避免遗留未参与训练的参数。

- 1cm 固定 voxel，origin 为 `[-2,-2,-2]`，沿用序列化空间边界。
- 在 voxel 聚合前通过 hand marker 排除手点；手与场景不会聚合在同一 voxel。
- 沿用既有4096点 cap及物体保留策略，再从有效场景点等间距选取最多256 token。
- scene token 附加当前XYZ的位置编码及 scene type embedding。
- hand token 由12D观察 MLP、hand ID、keypoint ID及 hand type embedding组成。
- goal token由6D MLP和可训练 `E_target` 组成，再附加独立goal type embedding。
- 256 scene +22 hand +32 goal拼接成310 token，进入4层128D/4heads/FFN512共享self-attention。
- 不添加null goal token；缺失goal用padding mask排除，正常scene tokens提供有效上下文。
- token顺序固定scene→hand→goal，hand head读取 `[256:278]`；接口fixture可缩减scene/goal数。
- PTv3训练保留原 stochastic depth和序列化顺序随机化；eval关闭顺序随机化。

没有手工输入 fingertip-object 距离或接触对应关系。物体 ID 只用于场景/标签组织，
没有规定某根手指必须关注某个物体。

## 4. 双预测头

**Scene head：**每个物体32个当前点的XYZ通过位置 MLP形成 query，cross-attend
全部共享 Z，再通过时间 embedding 和 MLP预测位移：

\[
\hat U\in\mathbb R^{B\times O\times24\times32\times3}.
\]

它预测已跟踪物体点，不声称当前已经覆盖全部背景 dense points。
未来 EgoDex dense tracks 属于另一次明确的数据与解码接口扩展。

**Hand head：**直接取共享 Z 的22个手 token；已通过trunk交互读取goal，每个 token
加上24个时间 embedding，通过同一个 MLP预测自身的未来位移：

\[
\hat V\in\mathbb R^{B\times24\times2\times11\times3}.
\]

不再使用528个独立 hand/time query 去从头读取 scene memory。手点身份从输入到输出持续保留。
两预测头最后一层使用小的非零初始化，以便首步 hand/scene loss 就能进入共享 trunk和PTv3。

## 5. 三域数据与预训练损失

复用原 `MixedWindows`、TRAIN/dev切分、source/category sampler和 TRAIN normalization。
原始三域文件不重写。数据源保持 OakInk2/GRAB/ARCTIC，source 权重为5:2:2。

当前32个 object point ID在所有24个未来步保持一致。现有 `effect` 是当前 anchor frame
中的物体相对变换，对当前点作用后生成标签：

\[
U^*_{o,j,i}=R_{o,j}P_{o,i}+t_{o,j}-P_{o,i}.
\]

手标签沿用实际手运动相对当前手位置的位移。目标物体的t+24实际endpoint在训练数据
适配层转换为当前点+delta，作为共享任务条件；中间24步完整轨迹仍仅用于监督。

损失是分别归一化的坐标 MSE：

\[
L_{pretrain}=\lambda_H\overline{L_H}+\lambda_S\overline{L_S},
\quad \lambda_H=\lambda_S=1.
\]

两项均除以固定0.05m尺度后计算 MSE，分别按自己的有效点/步归一化，不将所有scene和hand
点混在一个分母里。scene 的运动权重使用当前到未来的点位移幅度，阈值2mm、静态权重
floor0.1、sigmoid temperature5；静止物体仍有非零监督。
当前没有为 fingertip 单独乘大权重。

初始化加载已有 PW step50000 的 PTv3、scene projector和场景归一化；新增模块随机初始化。
这是空间编码器权重迁移，不声称复现原PW的action-conditioned temporal forward。
AdamW参数组：场景/PTv3 `1e-5`，其他模块 `1e-4`，weight decay0.01、clip grad1。
整个预测器均可训练。

评估按source分别报告hand first8/all24、scene moving/static EPE，以及scene的
`h1`、`first8`（1–8）、`middle`（9–16）、`h24`、`all24`。每个时间窗口同时报告
全部物体、target和non-target；目标身份来自当前 `goal_object_slot`，不按未来运动选目标。
缺失类别报告 `null` 和有效点计数，不能当作零误差。

每次验证同时输出 `goal_only/scene_*` 基线：目标点预测为 `(j/24)*delta_i`，
非目标点预测为零；不训练网络、不读取场景或手动力学，也不读取任何轨迹标签。
基线先核对目标当前点与scene点的同序对应；缺失goal点从目标基线的指标中排除，
所以比较时还须核对双方有效点计数。该基线是直线点插值，旋转中间态不保证刚体性。
三域的target h24理论上可仅靠输入endpoint达到近零误差；机器人计划endpoint可能与
实测终点有差异。必须结合first8/middle和non-target表现评估学习收益，h24不独立计作
动力学证据。基线随既有验证自动计算，本轮不另启动科学训练。

三域预训练的数据准备可与GPU计算重叠：每rank4个spawn workers、每worker两批预取、
persistent workers、pinned memory与non_blocking传输。worker内每source缓存最多512个
序列，复用只读映射；不修改原始数据、数据切分或采样概率。step/rank决定的batch顺序
保持不变，DataLoader使用独立Generator，不消耗模型主CPU/CUDA RNG。
已生成标签后，legacy action/effect/points等未被预测器使用的传输数组从训练batch移除。
运行参数写入provenance.execution，不进入模型config；完整模型、优化器、RNG可以
从旧checkpoint续训。实际四卡已从step2000恢复到r2，稳定约0.97–1.01秒/update，
30秒平均GPU利用率约90%。这是工程性能结果，不代表抓取或预测质量提升。
robot/replay当前仍沿用原入口，不默认启用这套human预取。

## 6. 机器人联合微调

2026-10-14用户将近期适配目标扩为完整DExplore 660条RL重定向轨迹。新增
`RLRobotWindows`读取重新补录的同执行机器人状态、真实link点、动态物体、实际规范化
命令与PD targets；原660 tensor只提供名单，其复制的人体字段不作为机器人手标签。
旧airplane入口仍可复现，当前正式适配通过corpus schema选择多序列入口。

全660均补录，按完整序列/物体分层约10%dev，每物体至少一条；所有窗口不能跨序列。
用户确认排除明显失跟：当前及未来24步物体位置距参考均<=10cm。每序列记录准入tick及
排除数；R归一化也只使用TRAIN准入窗口。该门不是抓取成功标准，零准入序列会被报告。
采样在准入序列内保持half startup(t<16)/half later，各阶段按序列均匀抽样；
预取仍使用独立Generator与固定step/rank种子。手、物体及native action loss合同保持不变。

微调配置为`robot_660.json`：全forecaster+新初始化Chunk-R，GT-tau anchor只更新R，
两卡每卡128/global256、20000步，human replay=0。已通过真实两轨迹单卡及双卡预取
四步工程检查；完整数据适配与闭环收益仍待验证。

第一阶段使用现有已通过 readiness/audit 的完整 airplane teacher demonstrations，
从实际FK手点、实际物体位姿和**同一行实际执行命令**构造 `(s,V*,U*,a*)`。
当前帧t的轨迹标签是状态t+1…t+24；动作标签是命令t…t+7。
goal endpoint来自已知计划 reference[t+24]，再与演员当前目标点相减生成delta；
不从演员未来的实测物体位置构造，也不统一改用整条任务的最后一帧。
在线尾部继续沿用 `reference[min(t+24,542)]` 的horizon截断。

TRAIN为完整env0…15，dev为env16…23。它们仍来自同一运动、固定初态的演示，
不是跨运动或扰动泛化证据。含clipping的24步窗口不准入，归一化仅用TRAIN行。

沿用128D Chunk-R：

| 输入/输出 | 合同 |
|---|---|
| 当前状态 | 87D：q18+dq18+当前物体坐标下的手点33+world物体pose12+物体速度6 |
| 手轨迹 | 24×33，右手、native link顺序、同一当前物体坐标系下的位移 |
| 输出 | 8×12 独立 native command |
| 原生执行 | 扩展到18D耦合命令并clamp；保留原 PD 转换，指关节尺度按原控制器处理 |

WAM语义点到native link的重排沿用 `WAM_TO_NATIVE`。没有新的形态坐标拟合。
R可以从TRAIN统计初始化，也可以通过 `--init-r` 显式加载已有匹配controller的Chunk-R。

机器人损失：

\[
L_{robot}=L_H+L_S+L_{A,\hat V}+L_{A,V^*}.
\]

两项action loss均为按R的TRAIN action std标准化后的8×12坐标平均L1，系数1。
`R(s,V_hat)` 的梯度进入整个shared forecaster和R；`R(s,V*)` 的GT锚定梯度只进入R。
PTv3、HandTokenEncoder、interaction、双预测头、GoalTokenEncoder和R一起更新。
不加载旧 action-conditioned World，不使用effect-consistency loss。

初期默认 `replay_fraction=0`，做机器人单任务适配。后续配置可开启human replay：
每步另外采样三域batch，按 `(1-r)*L_robot + r*L_human` 混合；human没有机器人动作损失。
未把失败演员后续运动标成expert trajectory；学生状态纠偏采集不是本次V0数据入口。

## 7. Chunk执行、身份与资源

原生执行使用两个独立runtime：graspenv运行完整Shared-WAM/R，归档torch2.0.1环境运行
IsaacGym。双方通过有大小上限、PID核对的本地JSON Unix socket通信。

默认 `K_exec=4`，可选1/8。查询输出8条命令后执行前K条，只有buffer耗尽才重新查询。
存储实际query tick、chunk index、命令、clipping、PD target和实际手/物状态。
这是同步前K步缓冲，没有复刻PointWAM的异步30步队列。

三行独立执行：teacher calibration、GT轨迹/R calibration、Shared-WAM/R。
GT手轨迹只进入校准行，不进入演员；演员仅使用自己实测H4和计划object goal。
完整542步报告hold/drop/placement；短工程smoke不评价抓取成功。
独立数组audit复算PD转换、chunk时钟、自己的查询历史与held帧数。

新schema保存整个模型，而非旧WAM的decoder patch。机器人checkpoint同时保存forecaster与R，
避免互换不匹配的pair。每个 `stepN.pt` 都是独立文件，保存优化器和每rank RNG以供resume。
验证objective创新低时立即保存完整权重，即使未到常规checkpoint间隔；原子维护
`best.pt`/`latest.pt`指向不可变`stepN.pt`。清理时保护当前best/latest。
长期运行可将checkpoint间隔与validation间隔分开；显式配置时保留里程碑和最近恢复点，
只清理当前run登记表中已被替代的非里程碑checkpoint。
config明确记录 `goal_encoding=current-point-horizon-delta.v1`，并单独记录
`task_conditioning=shared-scene-hand-goal.v1`。goal编码语义不变，条件路由改变。
旧absolute-goal checkpoint默认拒绝加载/续训，不因6D输入维数相同而静默改变语义；
ref1_1的hand-only delta checkpoint也拒绝作为新架构加载/续训。
新版本可以继续从PW场景权重初始化。旧checkpoint保留，没有自动转换其goal权重。
DDP使用NCCL同步梯度，各rank独立采样；`batch_size`是每rank大小。

输出在 `outputs/ptv3-shared-wam/<run_id>/`，scratch/cache在项目 `tmp/`。
训练有固定更新次数/时间上限，记录GPU显存、利用率与ETA；运行中源码变化或陌生GPU进程
使本任务停止。四卡80k配置每卡128/global512、每1000步验证、每2000步保存，
保留step1和每20k里程碑，wall-time最多7天。独立监督进程记录PID/退出码/GPU，
超过30分钟无进展时停止自己拥有的torchrun组。共享GPU上限6张、产物上限400GB；训练单run额外上限4GB，物理执行1GB/600秒。
非工程运行须先给Task-local experiment card和全局seed。工程checkpoint不静默升级为科学初始化。
