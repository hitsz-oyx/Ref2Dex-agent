# 从完整物体轨迹到 WAM 短目标：调度器的一手文献边界

日期：2026-10-18。Task：`wam-rl-policy`。本文是调研与设计讨论，不是实验结论；未运行训练或仿真。论文实际机制与本项目推论分开记录。

## 1. 需要先定的任务语义

**本任务已给完整 desired object trajectory，未来参考 `T_ref(u)` 是已知任务指令，在线调度可以读取。** 部署不可用的是尚未执行时的真实未来 `T_actual(t+H)`。因此无需先回归旧策略未来 endpoint；直接在已知 reference 上做目标选择、重定时与局部可实现性筛选才是当前问题。

给定完整物体轨迹，并不自动意味着必须按原始时间戳完成：

- **Trajectory tracking**：在指定时刻达到指定姿态；调度器允许多少延迟必须属于任务协议。
- **Path following**：保持路径顺序，时间进度由闭环控制选择。经典约束路径跟随明确不预先规定时间参数，并可额外加入速度要求。[Faulwasser & Findeisen, arXiv:1502.02468](https://arxiv.org/abs/1502.02468)

本项目建议：若用户只要求完成物体运动任务，可先采用“保持顺序、允许有限重定时”的协议；原时间戳作为速度先验。若任务涉及抛接、外部运动目标或必须按时到达，则不能把时间删除。此项是任务设计选择，不是已有结果。

调度器至少区分两个量：**已经完成到哪里** `phase`，以及**接下来一个 WAM 预测窗希望到哪里** `goal`。抓取准备时 phase 可以不变，goal 仍可以提供适度的未来抬升意图；二者不能强行使用同一个索引。

## 2. 最有帮助的一手方法

### Guided RL for Robust Multi-Contact Loco-Manipulation：最直接的相位机制

论文在 §3.2 使用

\[
\phi_{t+1}=\phi_t+\frac{\hat v_t^\phi+\sigma_1\delta_{v,t}}{T_{task}}\,dt.
\]

`v_hat` 由状态/参考/接触模式的 tracking reward 门控：误差大则接近零，恢复后接近名义速度；策略输出 residual 可加速、减速，甚至倒退以恢复接触。§5.1 观察最近参考状态搜索 NNS 容易卡住；作者将刷取静止 tracking reward 作为原因假设。表 1 的无 learned residual 版本已经接近完整方法，说明**可先检验状态门控，不必先联合训练高层**。[论文 §3.2、§5.1](https://arxiv.org/html/2410.13817v1)

边界：该方法拥有机器人整身参考和显式 contact mode；去掉关节参考后，多数任务失败。我们只有物体 SE(3) 任务，不能照搬其奖励或成功率；尤其接触前物体本来就不动，单用物体 tracking error 会错误地认为“已准备好”。[同论文 §3.1、表 1](https://arxiv.org/html/2410.13817v1)

### DexTrack：有完整手物参考，但不是在线子目标调度

§3.1 直接追踪 reference 的下一帧，使用手关节 reference 上的残差 PD target；奖励含物体位置/旋转、腕部、手指和 affinity。论文的 homotopy path / curriculum 是优化训练任务与生成示范的过程，不能解释为执行时根据当前状态重选短期目标。[DexTrack §3.1–3.3](https://arxiv.org/html/2502.09614v1)

可借鉴的是“生成参考”和“物理动作实现”分工；不能从其结果推出固定时钟足够，也不能将其示范监督的可执行手轨迹等同于我们生成的 τ。

### SimToolReal：达到当前目标再切换，但低层已学会抓取

§III-A 按物体 pose distance 阈值推进下一个 goal；§III-B 训练时专门包含从桌面抓取，再到达随机物体姿态。App A-D2 将 30Hz 参考降到 3Hz，并从物体离桌超过 10cm 的帧开始，裁掉静态 pre-grasp，使机器人立刻尝试抬升。[SimToolReal §III-A–B、App A-D2](https://arxiv.org/html/2602.16863v1)

可借鉴：在已知轨迹上按状态事件推进即可成为合理基线。边界：其执行器经过抓取/goal-reaching训练，不能把“达到才切换”本身当作 WAM+RL 已具备抓取能力的证明；10cm 是该数据处理设定，不宜移植成我们的通用门槛。

### Dex4D：对应点误差推进，更贴近点云目标接口

§III-D 对可见物体点与对应 target point 的平均距离打分，低于阈值才更新到下一组目标点；teacher 经过 privileged PPO 训练，student 通过 DAgger 获得可部署策略。[Dex4D §III-C–D](https://arxiv.org/html/2602.15828v1)

可借鉴：用对应点几何误差统一平移和旋转，而非只看物体中心；边界：可见点稀少/遮挡时需置信度处理，且其动作学习与我们的 WAM→τ→RL 合同不同。

### COIL：最近距离不可靠，可直接读完整有序任务

§3.1 只要求按顺序达到目标，不规定绝对时间；§3.2 明确指出稀疏任务和点跟踪噪声下，最近距离投影定位 progress 不可靠，改由时空 attention 融合任务与当前观测来预测动作，不显式输出目标帧索引。[COIL §3.1–3.2](https://arxiv.org/html/2512.05953v1)

可借鉴：保留剩余轨迹的局部形状和顺序，不能只给一个无上下文 endpoint。边界：这是训练过的 imitation action policy，不是可直接加载到我们 WAM 的 scheduler。代码里的表征裁窗若按 arc length 截断，也不能解释为该段物理可达。

## 3. 本仓库核查与建议：讨论稿，尚未实现

### 先修正问题定义

完整的期望物体轨迹是已知指令，后续参考位姿可以在线读取。必须隔离的是实际执行后才知道的真实未来状态。已有短目标 Probe 的 oracle 是后者，不应与未来参考混同。

因此当前要解的是“从已知参考中选择并重定时短目标”，而不必先学习“预测旧策略下一段会走到哪里”。旧混合行为 endpoint 回归未过门，不否定本问题。

### 已有实现具体覆盖了什么

- [short_goal.py](../../src/wam_rl_policy/short_goal.py) 的 `ShortGoal` 是状态/特征到刚体终点的回归头，没有完整轨迹或显式进度输入；[实验卡](../experiments/probes/P-20261016-wam-learned-short-goal.md) 的监督是旧行为实际48步未来，且不称可达性证书。
- [motion_reference.py](../../src/wam_rl_policy/motion_reference.py) 当前沿整任务终点方向截断5cm，旋转保持当前，每16个原生步刷新，WAM条件终点为48步；这是因果局部目标启发式，还没有保留完整参考路径的有序调度。
- [fast_bc.py](../../src/wam_rl_policy/fast_bc.py) 的 `batched_inputs` 接收位置，将同一个平移delta广播到32个物体点。因此完整SE(3)参考的旋转目前不能通过这个接口表达；应扩展为配对点的刚体位移，不能只改scheduler而继续丢弃旋转。
- 当前v3 WAM的goal token已经拼接同一点的start和delta，见 [v3 model.py](../../../ptv3-shared-wam-v3/src/ptv3_shared_wam_v3/model.py)；不能把旧独立ObjectGoalEncoder的对应关系问题直接归到此模型。
- 旧 [progress_goal_indices](../../../trajectory-policy/src/trajectory_policy/robot_context.py) 依赖平移匹配及参考时钟，未区分静止接触准备、旋转和回环。其[闭环Probe](../../../goal-point-wam/docs/experiments/probes/P-20261013-goal-point-wam-progress-reference.md) 在goal索引改变前动作就已分叉，结果仍UNCLEAR，没有隔离scheduler效果。
- [同条件WAM诊断](../experiments/probes/P-20261016-wam-task-readout.md) 在448个留出状态，物体32步预测从整任务goal条件145.56mm降为真实短终点条件14.29mm；同oracle几何插值20.29mm。它支持条件语义值得修正，不能证明可部署scheduler或RL收益。

### 建议的第一版：显式进度、有界前视、按状态推进

当前暂按“保持轨迹路径与顺序、允许变速”讨论；是否保留时间戳硬约束仍待用户明确。碰撞时机、冲击速度等若是任务条件，则不能仅靠重定时保证任务等价。

整体接口：

```text
已知完整物体参考 + 当前/过去手物状态 + 调度记忆
                      ↓
             短目标 g（固定物理时域H）
                      ↓
            冻结WAM → 手物运动参考tau
                      ↓
           RL(state, tau, reference_age) → action
                      ↓
             实际执行反馈回调度器
```

以下为本项目设计推断，并非文献已验证的组合：

1. **将已完成进度、当前局部匹配位置、前视目标分开。** 用完整SE(3)或对应物体表面点误差，在上次进度附近的有限参考窗口内定位；结合过去运动方向和已完成的有序里程碑，避免全局最近点匹配跳到回环后半段。准备抓取时，物体静止不表示接触准备已经完成。已完成里程碑只按实测达标记录；恢复目标可局部回退，不能把累计完成分数反复清零再刷进度。
2. **候选目标沿未完成的参考段选取。** 保留hold和若干不同前视距离的候选，以状态决定推进快慢。优先在参考相邻位姿间作平移插值和旋转插值，保留转折/接触等必要中间里程碑；单纯沿当前到最终点画直线可能绕过原路径约束。运动幅度限制只是启发式，不能宣称物理可达。
3. **固定WAM的物理时间含义。** 现模型按24帧@30Hz的0.8s终点训练；调前视量是在选“未来0.8s希望达到哪里”，并不把24个输出帧任意解释成2s或0.2s。WAM刷新周期、RL执行步数和参考轨迹进度是三个不同变量。tau生成后在刷新时的世界坐标锚定，按实际时间更新其age/误差；只执行短前缀，再用实测历史重算。
4. **区分准备、跟踪、恢复的控制状态。** 这些是调度状态，不假设所有任务都按抓起—搬运—放下发生。对需要抓起的任务，可结合手物距离、关节闭合、可用接触观测、物体响应与短时保持来判断准备情况；仅距离小不能证明抓稳。未准备好时保留下一项有意义的物体运动意图，控制前视幅度，避免参考已经推进到远处；滑移时缩短目标或进入局部恢复。
5. **先规则调度，后学小范围选择。** 最初用滞回和状态门控控制进度，超时报告未完成，不能自动跳过难点。如果实测发现固定前视经常过大/过小，再学习从有限候选中选目标或调整相位速度，避免一开始同时改变高层和执行器。
6. **恢复能力最终来自执行器。** 对同样静止的物体终点，“继续接近抓取、保持、释放”可能都成立；单终点未必能表达完整意图。先检查短暂抬起目标是否使WAM产生合理接近/闭合tau，以及RL能否实现。若均无有效抓取指引，下一步应补充任务preview/交互阶段条件并适配训练，或补执行器的接触学习；无限缩短目标和暂停进度不能创造不存在的技能。仅物体轨迹也未必明确给出释放/接触力意图。

刚体目标编码建议：设当前位姿为 `T_current`，目标为 `T_goal`，先算 `T_relative = inverse(T_current) @ T_goal`；对同一组物体局部点q，传入 `delta_i = R_relative @ q_i + p_relative - q_i`，保留旋转与对应身份，继承现有WAM点合同。

### 何时值得学习可达性

只有状态启发式已经暴露出明确决策瓶颈时，再用真实执行样本学习
`P(reach-and-maintain within H | state, goal, executor_version)`。该量依赖当前RL执行器，不是只由物体决定。成功与失败样本都要覆盖，物体/轨迹留出；策略更新后需核查校准。

WAM不接待执行动作，且预测显式受goal条件驱动，所以“它预测物体会到goal”不能作为goal可达性的独立证据。几何/关节/碰撞筛查也只是必要条件筛选。没有合格候选时应进入准备/恢复或明确失败，不能为了总能返回一个目标而伪造可达性。

### 最便宜且能改变决策的后续检验（本次均未执行）

**Blocker：核实tau执行器的局部资格。** 当前[同live state oracle tau卡](../experiments/probes/P-20261018-unidex-live-oracle-tau.md)仍标RUNNING，不能假定它已证明执行恢复。若连相同当前状态下的合理tau都不能被执行，scheduler对照结果主要受执行器限制；teacher/oracle只作诊断，不作为自主策略成功。

**Decision 1：短目标能否给出合适的局部交互参考？** 先用现有TRAIN的接近、接触、抬起、运输状态，展示当前手物状态、局部参考路径、各候选goal及WAM tau。比较整任务终点、按时钟短目标、按进度有界短目标，另保留hold诊断；由几何检查和可视化排除明显跳段、错误旋转或无行动指引。无需先重训大WAM。图示与预测误差不能证明物理可执行性。

**Decision 2：可变速调度是否改善真实有序执行？** 执行器具备局部资格后，在同初态、同WAM和同预算下比较时钟推进与状态推进。训练也应覆盖所部署的目标/刷新分布；若只在旧时钟策略推理时替换scheduler，结果仅说明该固定策略能否适应替换，不能代表scheduler方法的上限。使用真实有序里程碑完成率、SE(3)路径误差、抓持/跌落、耗时和恢复成功，不以预测进度作为成绩。

若Decision 2正向，再以相同scheduler比较WAM tau和几何参考，回答增益来自调度还是WAM。最终从任务初态完成全轨迹；中途状态初始化只作为局部技能诊断。高层奖励如后续加入，应基于实测有序完成，防止暂停刷静止跟踪分、跳帧刷进度和抛飞冒充抓取。

### 当前研究选择

建议先讨论并实现一个小的参考轨迹管理模块，负责SE(3)目标、进度记忆和可暂停的有界前视；保留 `WAM → tau → RL动作` 主线。旧endpoint回归继续作为历史诊断，不作为新调度器前置门。是否需要更丰富的意图条件，由准备/接触阶段的tau与真实执行结果决定，不在本次调研中预判。
