你觉得我们要不要先做一下critic排序的实验，先看看它能不能取代我们目前Y的位置？
我建议先做，而且这是现在**非常便宜、信息量很高**的实验。

但目的不是“又换一种 Cm 接法”，而是单独验证：

> **现有 PPO critic 能不能替代手工定义的 \(Y/U\)，给真实 candidate future state 排序。**

最干净的做法是直接复用 ref14 已有的真实 fork 数据：

\[
a_i \xrightarrow{\text{真实仿真8步}} s_{t+8}^i
\]

然后用冻结的 baseline critic：

\[
S_i
=
R_{t:t+8}^i+\gamma^8V(s_{t+8}^i)
\]

对 7 个 candidate 排序。**先完全不让 Cm 参与。**

重点比较三件事：

- critic 能否识别那几个 `baseline fail → candidate success` 的 rescue action；
- 会不会把原本成功的 baseline 排掉，产生 harm；
- critic ranking 和当前 GT-Y ranking 哪个更接近最终 \(Z\)。

如果结果是：

\[
\text{GT future state}+V
\]

已经能接近 rolling GT-Y 的判断，那么很好——以后可以把现在抓取特化的 \(Y\) 降级，主线变成：

\[
Cm\rightarrow \hat s_{t+8}\rightarrow V(\hat s_{t+8})
\]

critic 随 PPO 在线更新，扩展性明显更好。

如果**连真实 \(s_{t+8}\) 喂给 critic 都排不好**，那就说明当前 critic 本身还不足以取代 Y，暂时不要把 Cm 接过去。

唯一要注意的是：critic 同样是 policy-dependent 的，\(V^\pi(s)\) 会随 PPO 更新；但这反而比固定收集 \(Y^{\pi_{\text{baseline}}}\) 更自然，因为 critic 本来就会跟着当前 policy 在线更新。

**所以我会把这个实验列为下一步优先级最高的诊断：先测 `GT future state + critic`，不要训练新 Cm。**
