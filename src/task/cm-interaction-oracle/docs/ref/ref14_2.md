可以同步做，而且最好只做**不会依赖当前 Oracle-Y 结果、也不会污染下一步科学判断**的工作。

我建议并行开 3 条线，其中第一条最值得马上做。

### 1. 把这次漫长回放变成“下一阶段的数据资产”
现在每次 branch 不要只存最终 success。统一存：

\[
(H_t,\ a^{base},\ \delta a,\ F^{actual},\ E,\ I,\ Y_{\tau},\ Z)
\]

尤其是：

- candidate 实际 hand flow；
- 每隔 8 step 的 rolling \(Y\)；
- 最好再保留逐 step 的 height / force / proximity / contact proxy；
- candidate 是否改变实际 q、tip trajectory；
- 最终 Z 和第一次 failure 时间。

这样这次 Oracle 实验结束后，不需要重新跑一次才能研究：

\[
F^{actual}\rightarrow Y
\]

或者：

\[
E/I\rightarrow Y.
\]

这是当前最划算的同步工作。

---

### 2. 纯离线分析 Y，本轮就能做，不需要等 replay 完成

这个方向非常适合并行，而且不会改变主实验。

重点做四件事：

\[
\boxed{\text{Y temporal audit}}
\]

看不同 Y channel 到底什么时候开始分叉。例如：

- contact16/32；
- held16/32；
- height failure；
- held fraction。

不要只看最终组合：

\[
U(Y).
\]

看：

> 哪个分量最早预警失败？

可能最后发现真正有用的是：

\[
\text{height margin}_{32}
\]

而不是当前整个 Y8。

第二个：

\[
\boxed{\text{lead-time distribution}}
\]

统计：

\[
T_{\text{failure}}-T_{\text{first Y separation}}
\]

现在已经看到 29–47 steps，可以系统化。

第三个是：

\[
\boxed{\text{tie analysis}}
\]

为什么大量 candidate：

\[
Y_i=Y_j
\]

到底是：

- 动作真的没有影响；
- horizon 没覆盖到；
- Y 阈值太粗；
- 还是 candidate 实际 flow 太相似。

第四个是 Y 的连续化诊断。

例如当前：

\[
\mathbf 1[h<2cm]
\]

这种阈值 head 很粗。

可以离线看看连续量：

\[
h_{\min},\quad
\Delta h,\quad
v_z,\quad
\text{contact margin}
\]

是不是更早区分成功/失败。

注意这里只做诊断，不要现在重新定义 Y 并拿 test 结果刷一个新 Y。

---

### 3. 提前设计下一阶段 candidate space，但先别跑科学实验

当前 7 candidates：

- thumb ±
- middle ±
- grip+
- wrist-z+
- baseline

其实很多是“关节语义”，而不是“物理效果语义”。

可以离线把它们投到 hand-flow space：

\[
F_k\in\mathbb R^{N\times3}
\]

然后计算：

\[
\|F_i-F_j\|
\]

以及 fingertip / palm / thumb / object-relative flow diversity。

你很可能会发现：

> 看起来是 7 个动作，实际在 flow space 里只有 3～4 个真正不同方向。

那么下一批 candidate 就应该按 flow coverage 设计，而不是继续按 joint 名字设计。

这一部分可以完全用 FK / Jacobian / 已有动作数据做，不需要跑新的 PhysX。

## 4. execution layer 可以先做“工程准备”，但不要做 scientific claim

我们后面迟早需要：

\[
F^{desired}\rightarrow a.
\]

现在可以并行做最简单的 feasibility：

\[
\Delta P\approx J(q)\Delta q
\]

然后解：

\[
\Delta q^*
=
\arg\min_{\Delta q}
\|J\Delta q-\Delta F\|^2
+\lambda\|\Delta q\|^2.
\]

现在只需要回答：

> 给定一种局部 hand flow，现有 Inspire 独立关节能不能近似实现？

可以做：

- Jacobian conditioning；
- reachable flow subspace；
- mimic coupling；
- joint-limit feasibility；
- wrist / finger flow decomposition。

这不会依赖 Oracle-Y 最终是否成功。

但现在**不要**重新开启 execution predictor 训练。

---

## 5. 可以把下一阶段评估代码提前写好

如果 rolling GT-Y 最后通过，我们下一步一定会问：

\[
\text{Y predictor 要多准才能有用？}
\]

所以现在可以准备但不运行/调参：

- pairwise ranking accuracy；
- top-1 regret；
- oracle gain retention；
- action-shuffle placebo；
- environment OOF；
- same-state candidate ranking；
- noise injection：

\[
\tilde Y=Y+\epsilon.
\]

这样当前实验一结束，可以直接进入 Gate B。
