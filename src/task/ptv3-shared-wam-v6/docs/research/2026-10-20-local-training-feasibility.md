# 本地继续训练 WAM-v6 的可行性

核查日期：2026-10-20。范围是当前完整九源 v6、39526 条序列，不是此前视频使用的 v4，也不是一个缩小训练子集。仅检查代码、磁盘、环境和本地元数据，没有传输训练数据、重建缓存、删除文件或启动训练。

结论：代码和模型可以迁移；本地磁盘理论上能容纳一份完整训练缓存，但余量偏紧，GPU 排期和数据绑定尚未就绪。建议先将工作盘可用空间提高到至少300GiB，复用已有源数据，仅搬当前配方引用的缓存，不复制原始视频或历史缓存版本。

## 实测与估算

工作区 `/home2` 位于22TiB ext4 机械盘 RAID，快照可用227.34GiB；不把其他挂载点的剩余空间算入本工作区。未发现本地 NFS/CIFS 挂载。远端127.0.0.1:22023仍在 SSH banner 阶段超时，所以无法得到一次新的 NAS `du` 或立即复制缓存。

本地保存的完整准备计划与已完成事件普查覆盖39526条序列。按固定物体槽数的普查、可变槽数序列的全部本地数组头信息，得到6953250个序列时间帧、17982532个物体时间帧；可变槽源的物体帧数与历史完整普查一致。清单中所有本地处理后源文件均找到对应目录项；这不等于重新验证了每个数据内容和标签语义。所需人工手部参数包也能定位；622个升级后的 DexYCB/H2O packet 必须通过 `record.packet` 解析 `-surface-v1` 文件名，不能直接拼 `key.npz`。

当前 reader 使用未压缩 mmap NPY。依据 writer 的数组 shape/dtype 估算：

| 项目 | 新增空间 |
| --- | ---: |
| 双手778点表面 offset，float16 | 60.46GiB |
| 2048查询点 contact float16 + part uint8 | 102.90GiB |
| joints、有效性、物体位姿等数组 | 4.66GiB |
| reader 必需的事件数组 | 0.10GiB |
| 数组小计 | **168.11GiB** |

| 必须保留的磁盘余量 | 20GiB |

当前只多出约14.22GiB，不宜承担其他任务继续写盘、重复准备版本、失败 staging 或“完整打包文件+解压目录”双份占用。推荐再释放约80–100GiB，目标可用空间至少300GiB。既有检查点清理草案约59.6GiB仅是待引用审计的候选，不是获准删除清单，也未计入可用空间。

估算只覆盖当前训练 reader 的必要缓存，不包含所有原始数据、预处理历史、完整事件诊断数组或远端整个工程。不是实时 NAS 测量。原始处理后源与参数包已在本地，复用它们无需再占相同空间。

## 工程量与恢复边界

本地 `graspenv` Python3.8.20 / Torch2.4.1+cu121 能实际导入 v6 model 和 reader；未运行 CUDA 训练。完整 step23758 检查点已在本地验证，1186363152bytes，包含568份 optimizer state、world3 与3份 RNG。训练还需要原配方、TRAIN normalizer JSON、索引/strata 和上游缓存元数据；完整检查点自身没有保存整套数据配方与 stats JSON。

主要工作：

1. 收集当前 v6 recipe、v5 parent、stats、索引/strata、hand/contact/event 元数据，按现有配方引用范围列出唯一需要的文件。避免同时搬旧 hands、hands-r2、旧 contacts 等版本。
2. 处理绝对路径与元数据绑定。V6 recipe 校验上游身份，checkpoint 又绑定 manifest+stats。简单替换路径会触发恢复拒绝；需要保留逻辑数据身份的路径映射，或者明确验证并记录等价数据的重新绑定，不能绕过检查。
3. 若 NAS 可独立访问，直接获取现成缓存最省工作；若完全无法访问，则利用本地源与参数包重建手表面、接触、事件及配方，重新核对对象/帧/窗口身份和原归一化。已有准备脚本可复用，但不能声称已确认离线逐位恢复整套冻结配方。
4. 取得 GPU 后做实际 reader 抽样、短恢复更新、DEV 与保存/再次恢复检查，再考虑长训。机械盘上的数十万小文件随机读取可能限制吞吐，需要实测，不能沿用远端4090的 ETA。

粗略人力估计（未实施）：已有现成 NAS 缓存可读时，路径/配方适配与验证约半天至一天，另加未测速的传输耗时；完全本地重建约1–2天工程与验证，实际缓存生成/I/O时间另计。输入或冻结索引存在差异时可能更久。

## GPU 与训练配置

本地8×3090，每卡24GiB。核查时0–3各占约21–23GiB，4–6的现有PPO各占约15GiB，7有monica任务约6.7GiB，均不是空闲卡。本次没有停止或抢占任何任务；瞬时利用率0不代表显存已释放。继续遵守全局GPU边界。

当前停训点是world3/local64/global192。历史远端该配置峰值 allocated约10GiB，说明独占3090值得做容量 smoke，但本地未实测，不能保证所有batch的reserved峰值。三卡同batch迁移最少改变训练合同。现有正式 launcher 只支持3/4卡；改为1/2卡需要额外的拓扑恢复与有效batch设计，当前没有梯度累积实现，不能仅改 CUDA_VISIBLE_DEVICES。

原四卡 local128/global512 配置不应直接搬到繁忙的24GiB卡上。若只做接触几何或滚动稳定性的少量样本 Probe，空间可大幅缩小，但必须声明是独立子集实验，不能称为原完整九源续训。
